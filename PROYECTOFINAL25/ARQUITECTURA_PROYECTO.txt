1. ¿QUÉ TIPO DE ARQUITECTURA TIENES?
================================================================================

RESPUESTA: ARQUITECTURA MODULAR (NO son microservicios)

¿Por qué?
- Tienes UN SOLO SERVIDOR corriendo en el puerto 3000
- Todo está en el archivo servidor.js
- Usas UNA SOLA BASE DE DATOS PostgreSQL
- Los "módulos" están separados por carpetas pero todos funcionan juntos

DIAGRAMA:
┌─────────────────────────────────────────┐
│    UN SERVIDOR (Puerto 3000)            │
│  ┌─────────────────────────────────┐   │
│  │  Express.js (servidor.js)       │   │
│  │  ┌────────┐ ┌────────┐         │   │
│  │  │ Rutas  │ │Contro- │         │   │
│  │  │        │→│ladores │→Modelos │   │
│  │  └────────┘ └────────┘         │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
            ↓
    ┌──────────────┐
    │  PostgreSQL  │
    │   (1 BD)     │
    └──────────────┘

Microservicios sería:
Servidor Auth (Puerto 3001) → BD Auth
Servidor Pagos (Puerto 3002) → BD Pagos
Servidor Reservas (Puerto 3003) → BD Reservas
❌ NO tienes esto

2. FLUJO DE DATOS COMPLETO (Frontend → Backend)
================================================================================

PASO 1: Usuario abre la página web
───────────────────────────────────

📱 Navegador
   ↓
🌐 Frontend (Puerto 5173) - Vue.js
   ↓ Lee archivo
📄 index.html
   ↓ Carga
📄 main.js
   ↓ Inicializa
📄 App.vue (Aplicación principal)
   ↓ Carga
📄 router/index.js (Rutas de las páginas)
   ↓ Muestra
📄 views/InicioView.vue (Página de inicio)

Archivos clave Frontend:
• main.js → Punto de entrada, como el interruptor principal
• router/index.js → Mapa de páginas (decide qué vista mostrar)
• stores/auth.js → Memoria temporal (guarda usuario logueado)
• services/api.js → Teléfono (llama al backend)


PASO 2: Usuario hace click en "Login"
──────────────────────────────────────

👤 Usuario → Click "Iniciar Sesión"
   ↓
📄 LoginView.vue (Formulario)
   ↓ Usuario escribe email/contraseña
🔌 services/api.js → autenticacionService.iniciarSesion()
   ↓ Axios hace HTTP POST
🌐 http://localhost:3000/api/autenticacion/iniciar-sesion


PASO 3: Backend recibe la petición
───────────────────────────────────

🚪 BACKEND (Puerto 3000)
   ↓ Express recibe petición
📄 servidor.js → Lee URL "/api/autenticacion/..."
   ↓ Busca ruta
📁 src/rutas/autenticacion.js → router.post('/iniciar-sesion')
   ↓ Llama a función
📁 src/controladores/autenticacionControlador.js → iniciarSesion()
   ↓ Busca en base de datos
📁 src/modelos/usuarioModelo.js → buscarPorEmail()
   ↓ Consulta SQL
🗄️ PostgreSQL → SELECT * FROM usuarios WHERE email = '...'
   ↓ Devuelve datos
📁 Modelo → Devuelve usuario
   ↓ Compara contraseña
📁 Controlador → Genera token JWT
   ↓ Responde
🌐 Respuesta JSON: { token: "...", usuario: {...} }


PASO 4: Frontend recibe la respuesta
─────────────────────────────────────

🔌 services/api.js → Recibe respuesta
   ↓ Guarda en
📦 localStorage (navegador)
   ↓ Actualiza
📦 stores/auth.js → usuario = {...}
   ↓ Redirige a
📄 views/DashboardView.vue

5. FLUJO COMPLETO DE UNA RESERVA CON PAGO
================================================================================

1️⃣ Usuario busca artistas
   LoginView.vue → POST /api/autenticacion/iniciar-sesion
   
2️⃣ Ve marketplace
   ArtistasView.vue → GET /api/artistas
   
3️⃣ Click en artista
   ArtistaDetalleView.vue → GET /api/artistas/:id
   
4️⃣ Solicita presupuesto
   SolicitarPresupuestoView.vue → POST /api/contratos/solicitar
   BD: INSERT INTO cotizaciones_eventos
   
5️⃣ Artista recibe notificación
   ResponderSolicitudView.vue → GET /api/contratos/solicitudes/:id
   
6️⃣ Artista envía propuesta
   ResponderSolicitudView.vue → POST /api/contratos/solicitudes/:id/propuesta
   BD: INSERT INTO propuestas_artistas
   
7️⃣ Cliente ve propuesta y decide pagar
   ProcesoPagoView.vue → GET /api/pagos/propuestas/:id
   
8️⃣ Cliente selecciona QR
   PagoQRView.vue → POST /api/pagos/generar-qr
   Genera QR con librería 'qrcode'
   
9️⃣ Cliente confirma pago
   PagoQRView.vue → POST /api/pagos/procesar
   BD: INSERT INTO pagos
   BD: INSERT INTO contratos (¡Reserva creada!)
   BD: UPDATE propuestas_artistas SET estado = 'aceptada'
   
🔟 Confirmación
   ReservaConfirmadaView.vue → ¡Éxito!

GLOSARIO DE TÉRMINOS
================================================================================

Frontend: La parte visual de la aplicación que el usuario ve (navegador)
Backend: El servidor que procesa la lógica de negocio (Node.js/Express)
API: Interfaz de comunicación entre frontend y backend (HTTP/JSON)
Ruta: URL que define un endpoint de la API (/api/contratos/solicitar)
Controlador: Función que maneja la lógica de una petición
Modelo: Función que interactúa con la base de datos (SQL)
Middleware: Función que se ejecuta antes de los controladores (auth)
JWT: Token de autenticación (JSON Web Token)
ORM: No usas ORM, haces consultas SQL directas con pg
Pool: Conjunto de conexiones reutilizables a PostgreSQL
REST: Estilo de arquitectura para APIs (GET, POST, PUT, DELETE)
CORS: Permite que frontend (5173) llame a backend (3000)
Docker: Contenedor para ejecutar PostgreSQL aisladamente
